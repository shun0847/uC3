■ はじめに

　uNet3付属のサンプルソース「簡易ファイルシステム」について説明します。


■ 機能概要

　弊社提供ネットワークアプリケーションの一部は動作にファイルシステムが必要と
　なります。「簡易ファイルシステム」には最低限のANSI準拠ファイル操作用APIと
　同じインタフェースを備えており、実際のファイルシステムの代わりにネットワー
　クアプリケーションの動作評価用にご利用頂けます。
　
　実際にユーザアプリに組み込んでご利用される場合、ソースコードの適宜変更や、
　十分な動作検証を行った後、ご利用願います。
　
　・以下ファイル操作用API(ANSI準拠)、ディレクトリ操作用API(POSIX準拠)は機能します。
    fopen
    fclose
    fread
    fwrite
    fseek
    remove
    rename
    feof
    opendir     // ドライブルート指定時のみ動作 (C:\, A:\)
    readdir
    closedir
    stat        // 1981-01-01の日付のみ取得

　・以下ディレクトリ操作用API(POSIX準拠)は機能しません。
    mkdir
    rmdir

　・排他制御を行いません。(複数タスクから呼ばれた場合は動作保証出来かねます)
    
　・簡易ファイルシステム使用前に初期化処理(ffs_ini())をコールして下さい。


■ ファイル構成
    ・\sample\ffsys.c                       簡易ファイルシステムのソースファイル
    ・\sample\ffsys.h                       簡易ファイルシステムのヘッダファイル
    ・\{サンプルフォルダ}\ffsys_cfg.h       設定ファイル


■ 設定ファイルの記述例 (ffsys_cfg.h)

    #define CFG_FFS_DRV_NAME     'C'     /* ドライブレター */
    #define CFG_FFS_FILE_CNT     4       /* 最大ファイル数 */
    #define CFG_FFS_FILE_LEN     4096    /* 最大ファイルサイズ */

※コンフィグレータ付きのパッケージの場合、コンフィグレータ起動後 [TCP/IP]
  →[ネットアプリケーション]→[File System]→[eForce簡易ファイルシステムを使用する]
  より同様の設定が行えます。


■ 実際のファイルシステムとの違い

実際のファイルシステムと違い、フォーマット・セクタ・クラスタ・フォルダなどの
概念がない単純なRAM領域(構造体変数)です。ファイルの読み書き・削除・リネームは
行えますが、フォルダ操作は出来ません。RAM配置のため揮発性です。
